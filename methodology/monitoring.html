# Quarterly monitoring demonstration

This release includes a real one-question baseline snapshot and a separate synthetic demonstration. Synthetic outcomes are never observations, coding rows or study metrics. The comparison module is a prototype for review routing, not a validated statistical alert service.

## What is demonstrated

- The first positioning question selected in the reviewed narrative supplies the observed baseline. In Good Culture, this is the protein question.
- Three illustrative next waves show unchanged credit, a decline of one quarter of the denominator, and a change in recorded model metadata. Future values are invented and have no supporting answer records.
- Compare exact question/context, market, brand, population, layer, metric, codebook, engine roster, repeat labels and recorded model/mode/sign-in/context-flag settings. Metadata is also grouped by engine. A changed denominator is held for review rather than silently compared.
- A metadata mismatch produces HOLD with no numerical change estimate. Equal recorded metadata permits a descriptive comparison, not a claim of experimental control: hidden account, retrieval and model changes remain possible.
- Under equal recorded settings, an absolute movement of at least 25 percentage points triggers REVIEW. This arbitrary demonstration rule is not statistical significance, an underwriting threshold or a calibrated monitoring policy. Repeats are not independent consumers.

## How to run

Build a reviewed brief in each wave. Each new brief includes data/monitoring_baseline.json for its selected positioning question. From code/, use:

    python -m report.monitoring BASELINE_SNAPSHOT.json NEW_WAVE_SNAPSHOT.json NEW_COMPARISON.json

The command reads saved snapshots and writes a new comparison file; it makes no engine calls. Inspect changed metadata before treating an answer change as a brand trend. Never use data/monitoring_demo.json or its synthetic cases as collected future evidence. Snapshot generation is tied to the reviewed question selection, not hardcoded to cottage cheese.

This is a one-question end-to-end demonstration, not a complete all-brand quarterly dashboard. Production monitoring would add per-engine/question coverage, missing-cell and context diagnostics, evidence links for both waves, reviewed alert thresholds, and a calibrated assessment of repeat variation. Collect engine answers can prepare or collect a new wave; Build investment brief renders it after review and registration. Neither workflow schedules monitoring or approves comparisons.

## Birkenstock preview

demonstrations/birkenstock/ contains a fresh offline preview generated by automation/run.py with the shipped category profile: exact planned requests, configuration, empty review templates and a preview manifest. Attempted and captured requests are zero. This demonstrates configuration reuse, not footwear research or live API compatibility. API keys, explicit model choices and a small live pilot remain necessary before collection.
