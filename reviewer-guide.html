Review contract

New collection requires approved coding, context/exclusion decisions and interpretation. Registered packages seal input hashes and bind the narrative to the evidence, configuration and calculation fingerprint. Build-time validation checks those bindings. Approved inputs must be committed before building.

Configuration changes

Quarterly runs retain comparable prompts, context, repeat plans and coding rules, with model/mode changes recorded. A category change replaces prompts, competitors, attributes and reviewed interpretation; collection, validation, calculations and rendering carry over.

The Birkenstock reuse example is an uncollected category example. API and browser evidence remain separate series. Live API collection is unpiloted; adapters use offline fixture tests.

Publication baseline

Sanitized answer text, coding, chart tables and citation attachments preserve the reviewed numeric results. Original interface captures remain private. Citation mapping is selective; factual verification is deferred. Monitoring scenarios are synthetic. Publication record.
