# Coding guide v2.0.0

Unit: one engine × exact prompt × repeat, within main or supplement. Q1–Q9 are unprompted brand discovery; Q10–Q12 name brands. Keep layers separate. Repeats describe answer variability, not independent consumers. Do not infer market share, demand weights or causal sales effects.

## Review workflow

Start with outputs/good_culture_2026_10_v2/calibration_12.csv. Open each candidate text and consult the original DOM/AX, screenshot and JSON where boundaries are unclear. Candidates are not clean answers: they may retain source snippets, ads, product cards and interface labels. Copy only the assistant's answer into cleaned_answer. Preserve prose, lists and tables; remove UI, sponsored placements and standalone related-result snippets. Products explicitly recommended within the answer count; unrelated shopping cards do not. AX captures require careful boundary reconstruction; do not treat every text node as answer prose.

Review the twelve examples, document edge cases in notes, then freeze revised rules under a new version before full coding. Human review means the designated reviewer (user or assistant performing explicit evidence review); no additional user approval gate is required.

## CSV fields

- review_status: pending / needs_review / approved. Approved means evidence has actually been checked, not merely generated by a classifier.
- cleaned_answer: reviewed answer-only transcript. Do not improve engine claims or repair missing text from imagination.
- mentioned_brands_json: distinct canonical brands in answer prose, e.g. ["Daisy", "Good Culture"]. Count negative mentions too. Empty list means reviewed and absent, not missing.
- recommended_brands_json: brands explicitly offered as a purchase/try choice, including conditional alternatives. A factual comparison or mention is not a recommendation.
- first_recommendations_json: the answer's leading overall purchase choice. Use multiple brands only for an explicit equal joint lead. If it offers only distinct conditional choices without an overall lead, use [] and record conditions in notes. First textual mention is not enough. Ties receive 1/k credit for each of k co-leaders; report this convention.
- reason_tags_json: answer-level tags from protein, ingredients, live_cultures, taste, texture, price, availability, sodium, lactose, organic, other. These do not by themselves attribute a reason to a brand; record brand-specific reasoning and conditions in notes/excerpts before H1–H3 interpretation.
- premium_assessment: not_applicable / justified / conditional / not_justified / unclear. Code justified only when the answer explicitly endorses the premium; Q10's premise does not establish real shelf prices.
- substitutes_json: explicitly recommended replacements for the focal brand, not all competing brands mentioned. Usually relevant to Q11; capture equivalent-benefit reasoning in notes.
- supporting_excerpt: exact supporting text copied from raw evidence (whitespace normalization allowed). For AX evidence use a contiguous captured fragment. This is minimum provenance, not proof every field has been validated; retain additional excerpts in notes.
- quality_decision: include / exclude, required on approved rows. quality_reason explains the decision. Known defective answers default to pending; inclusion requires an explicit documented assessment. Excluded rows do not need fabricated codes.
- reviewer, reviewed_at_utc: reviewer name/identifier and ISO timestamp of review.
- coder_prompt_version, coder_model: required in practice when AI coding is used; leave blank for manual-only coding. Save the exact classifier prompt and raw classifier output in a new dated folder under review/. Do not silently recode with a different model.
- notes: conditions, variants, brand-specific reasons, uncertain attribution and additional evidence excerpts.

Canonical names: use Good Culture, Daisy, Breakstone's, Knudsen, Lactaid; normalize capitalization and possessives. Keep other named brands as their names rather than collapsing into Other. For store brands use "Private label: <store/brand>"; do not merge unnamed generic cottage cheese into a brand. Product variants remain in cleaned_answer/notes; product-level analysis will need a separate long-form product table.

## Hypotheses and denominators

H1: compare Good Culture fractional first-recommendation rate on Q3/Q4 against Q1/Q2 within engine. Q5 is separate. Retain question-level results, then average question rates equally if presenting a group comparison. H2: Q6 versus Q1/Q2, using same convention. H3: manually synthesize Q10–Q12 with substitutes, premium assessments and brand-specific reasons; no automatic moat score. H4: compare matched prompts across engines and repeats; inspect citation domains separately with missingness disclosed. Current scorecard provides engine/question inputs, not final hypothesis judgements.

Always show collected n, reviewed included n and excluded/pending n. Never treat missing/unreviewed codes as zero. Source links include related results, product/image links and redirects; only claim-mapped evidence can be called a supporting citation. Cited domains do not prove causal influence.


## Version 2 schema and settled calibration rules

The user accepted the v1 calibration interpretations, then authorized these refinements. The old code, config, codebook and calibration remain under versions/v1.0.0 and review/good_culture_2026_10. V2 starts a separate run; raw collection is unchanged.

Three linked tables are authoritative: coding.csv (one row per observation), brands.csv (one row per mentioned brand per observation), and claims.csv (one row per selected material brand-specific claim/condition/variant). Preserve distinct national and private-label brands. “First recommendation” means the explicit overall purchase lead for the question's stated shopper need, not a universally best brand. An explicit best-all-around answer qualifies even if preferences are acknowledged. Branch-only branded comparisons get conditional_only; specialized maximum-protein suggestions do not displace an explicit overall lead. This is different from an explicit equal tie.

### New observation fields

- overall_lead_status: single / tied / conditional_only / no_recommendation / unclear. Single requires exactly one leading brand; tied requires at least two explicit co-leaders. Conditional_only requires recommended brands but no overall lead. Report no-lead counts separately; do not describe zero first-choice credit as brand rejection.
- first_brand_mentioned: first canonical brand in cleaned answer prose/table, excluding prompt, UI, related sources and ads. This presentation measure remains separate from purchase endorsement. Original raw order must be checked where accessibility reconstruction is uncertain.
- context_flags_json: list of observed personal/location/account-context signals; [] means no visible signal found in the reviewed answer, not proof no personalization occurred. context_review_status must be reviewed before approval. context_evidence_json contains exact excerpts for flagged signals.
- premium_evidence_json: exact excerpts supporting justified/conditional/not_justified; not_applicable and unclear need no invented support. Any ambiguity stays in notes until adjudicated.

### Brand rows

recommendation_type: leading / co_leading / conditional / alternative / comparator / negative_only / mention_only. All first four count as recommendations; comparator never does. Each brand requires mention_evidence. Recommendations require recommendation_evidence; leaders additionally require lead_evidence; substitutions require substitute_evidence and is_substitute=yes. One excerpt may support several fields only where it actually establishes those conclusions. A heading or table cell can establish an option when its surrounding authored answer clearly recommends the table's entries; source snippets cannot. The first calibration expansion conservatively uses conditional for secondary recommendations; separate alternative where the text offers an unqualified secondary choice.

### Claim rows and sources

claim_type: benefit / drawback / condition / variant. value is the coded feature or variant; evidence_excerpt is exact raw evidence (whitespace normalization allowed). A row is an attribution to the engine, not a verified fact. Include material advantages, trade-offs, purchase conditions and named variants; this is not an exhaustive inventory of every sentence. Do not merge Simply/Organic or different serving sizes when making factual product comparisons. Keep actual claim-level quantities in excerpts; structured numeric product comparison is a later analysis layer.

citation_status: not_mapped / engine_citation_mapped / no_visible_citation / unavailable. Only use mapped after checking the citation attached to that claim and preserving its observed URL in observed_source_urls_json. The presence of a URL anywhere on the answer page is insufficient. Fact checking uses a separate fact_check_status (unverified_engine_claim / supported / contradicted / mixed / not_assessed), verification_source_url and verification_note. Independent verification links are not engine citations. Health/nutrition, sourcing and prices need product/serving/date comparability. Do not call repeated citations independent validation.

### Quality and sensitivity rules

Retain context-flagged main observations in the descriptive baseline with explicit limitations; separately compare matched strata excluding flagged observations. Don't silently replace or delete unfavorable/contaminated answers. For the truncated supplemental Copilot Q1, default to exclusion from complete-answer recommendation metrics; any usable-section qualitative analysis must label partial content. Main and supplement remain separate. Exclusions count toward completed review but not metric denominators; report collected, included, excluded and pending n per cell.

Mechanical excerpt/hierarchy validation does not establish semantic correctness, complete claim coverage or intercoder reliability. A second evidence pass should hide original proposed codes, sample harder cases beyond these twelve and record disagreements by field before claiming reliability. No formal independent-human agreement statistic is available from a single assistant reviewer. Historical engine model identity or prompt brand order cannot be randomized retroactively. Q10's assumed premium, organic variant differences and original personal context must remain stated limitations.
